# Glossary (EN ↔ DE)

Binding terminology for this portal and for translations. English is the
primary docs language; German translations use these pairs consistently.

| Deutsch | English | Notes |
| --- | --- | --- |
| Mandant | tenant | Isolated customer unit; never "customer" |
| Objektdefinition | entity metadata / entity definition | The metadata document describing a business object |
| Auswahlliste | lookup | Parameterized selectable value list |
| Pickliste | picklist | Static picklist on an entity field (`pickvalue` entries) |
| Auswertung | statistic | Chart/map/pivot analytic view |
| Dokumentation | documentation | Field-level help text metadata |
| Benachrichtigung | notification | Notification definition (document service) |
| Abonnement | subscription | User's e-mail subscription to a notification |
| Berechtigung | right | Action permission `{application}.{entity}.{action}` |
| Stammdaten | master data | Generic term for tenant business data |
| Anhang | attachment | Binary file on an entity record (storage service) |
| Vorhersage | estimation | ML prediction result |
| Schnittstelle | API | Any HTTP interface |
| Verarbeitungsstatus | processing state | Per-entity lifecycle state with successors |

## Terms that do **not** exist as domain concepts

Do not invent these: there is no platform domain term *catalog* (Katalog), no
generic *requirement* (Anforderung) concept — `requirement` exists only as an
application-specific entity name in a particular tenant deployment. `unit` and
`person` are claim types, not domain entities.

## Name collisions to watch

- Export records: `ExportResult` (repository-layer result carried through the
  meta service) and `GenericExport` (the generic service's tenant-level
  equivalent) describe the same payload — `FileName`, `MediaType`, `Data`.
  Treat them as one concept on the wire.[^1]

[^1]: `ballware-generic-service/src/Ballware.Generic.Tenant.Data/GenericExport.cs`, `ballware-meta-service/src/Ballware.Meta.Data/Public/Export.cs`
