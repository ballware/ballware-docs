# ballware platform overview

ballware is a **low-code platform for business applications**. Application
screens (lists, forms, tabs, statistics) are not coded per application:
entities, lookups, page layouts, and rights are described as **metadata** and
rendered at runtime by a shared Angular web client against a set of
independent .NET services.[^1][^2]

:::info Documentation scope
These docs cover exactly nine repositories — `ballware-angular`,
`ballware-meta-service`, `ballware-generic-service`, `ballware-document-service`,
`ballware-storage-service`, `ballware-ml-service`, `ballware-keycloak`,
`ballware-apigateway`, and `ballware-docker-compose`. Every statement is sourced
from the **`main` branch** of these repos (state of 2026-11-19); the main branch
carries the current stable versions. See [Repositories](/docs/repositories) for
the version markers.
:::

## Capabilities

| Capability | Component | Notes |
| --- | --- | --- |
| Metadata-driven UI | **ballware-angular** (webclient + `dx-renderer`) | Renders grids and forms from `GridLayout`/`EditLayout` metadata using DevExtreme[^1] |
| Tenant business data | **ballware-generic-service** | Generic CRUD/query engine executing metadata against per-tenant schemas; exposes an MCP endpoint for AI agents[^2] |
| Metadata management | **ballware-meta-service** | Stores entities, pages, lookups, pick values, documentation, exports, jobs, statistics[^3] |
| Documents & reporting | **ballware-document-service** | DevExpress XtraReports definitions, Blazor report designer/viewer (public base URL `reporting.ballware.de` in the app config), PDF and e-mail jobs[^4] |
| Attachments & object storage | **ballware-storage-service** | Binary attachments and temporary files; blob providers for Azure Blob Storage and MinIO[^5] |
| Machine learning | **ballware-ml-service** | AutoML training and prediction API (purpose reconstructed from the code; the README is content-free)[^6] |
| Identity & access | **ballware-keycloak** | OAuth2/OIDC identity provider (Keycloak 26.8.2 with ballware SPI extensions), realm `ballware`[^7] |
| API gateway | **ballware-apigateway** | Configuration-driven YARP reverse proxy: validates bearer tokens, applies CORS, routes `/meta`, `/tenant`, `/generic`, `/document`, `/storage`, `/ml`, `/ai` to the services, serves MCP protected-resource metadata[^9] |
| Evaluation stack | **ballware-docker-compose** | Single-machine stack that builds every component above straight from its `main` branch[^8] |

## Application model

A *tenant* (Mandant) is an isolated customer deployment unit of the same
platform: its business data lives in its own database schema (provisioned and
held by the generic service), and its application behavior is shaped by tenant
metadata (navigation, entity definitions, templates, scripts). See
[Tenancy](/docs/tenancy) and the [metadata model](/docs/metadata-model).

Application behavior that goes beyond CRUD is expressed in **scripts**
(JavaScript, executed with Jint on the server): lifecycle and rights-check
scripts in the generic service's scripting layer, plus client-side layout and
rights hooks in the web client.[^2][^1]
